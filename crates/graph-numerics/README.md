# Graph Node numeric primitives

`graph-numerics` implements the numeric behavior needed by a native Aerodrome
reducer. It uses **bigdecimal =0.1.2** and **num-bigint =0.2.6**, exactly as Graph
Node v0.44.0 commit `77823b5a7adc4eac4abf03202c8dd7cb00dea31d` does. The decimal
normalization wrapper follows that commit's
[`bigdecimal.rs`](https://github.com/graphprotocol/graph-node/blob/77823b5a7adc4eac4abf03202c8dd7cb00dea31d/graph/src/data/store/scalar/bigdecimal.rs),
[`bigint.rs`](https://github.com/graphprotocol/graph-node/blob/77823b5a7adc4eac4abf03202c8dd7cb00dea31d/graph/src/data/store/scalar/bigint.rs),
and [WASM boundary](https://github.com/graphprotocol/graph-node/blob/77823b5a7adc4eac4abf03202c8dd7cb00dea31d/runtime/wasm/src/to_from/external.rs).
No Graph Node runtime or database dependency is pulled into the portable crate.

## Explicit normalization boundaries

Let `n` be Graph Node's `with_prec(34)` and trailing-zero removal. For negative
numbers **n is not idempotent**. A simple 34- or 35-digit precision model is wrong.

| API | Boundary represented |
|---|---|
| `from_bigint`, `from_asc_parts` | A raw AssemblyScript decimal crossing into the host once: n(raw). |
| `from_db_text` | Graph Node's database text deserialization: n(text). A later WASM-to-host crossing must call `cross()`. |
| `host_from_string` | A host string-parsing result used by a later host operation/store: n(n(parse)). |
| `plus`, `minus`, `times`, `divided_by` | Inputs already observed at the host boundary; the returned host result plus its next crossing: n(n(op)). |
| `cross` | One additional explicit normalization, useful for a stored value read back into a mapping. |
| `to_wire_exact`, `from_wire_exact` | Lossless coefficient/scale checkpoint encoding. No normalization on restore. |
| `to_block_changes_wire`, `from_block_changes_wire` | Strict v1 framing: refuse non-fixed points instead of truncating them. |

For example, raw `-85070591730234615865843651857942052863` becomes coefficient
`-85070591730234615865843651857942052`, scale `-3` after one crossing. A second
crossing changes it to coefficient `-8507059173023461586584365185794205`, scale
`-4`. The exact checkpoint API preserves the former; the current BlockChanges v1
contract refuses it. There is deliberately no implicit `FromStr` or Serde
implementation that could renormalize a checkpoint during restore.

This does **not** finish end-to-end Aerodrome support for once-normalized negative
raw Swap amounts. Zero-decimal tokens can produce these values at and around
`-(2^116 * 10^3)`. Their eventual admission needs a coordinated wire-domain,
mapping-host restore, and engine numeric-writer change. This crate preserves
the information needed for that change without weakening the v1 validator.

## Operations and limits

Decimal arithmetic and division are performed by the pinned dependency. All
fallible operations return `Result`; zero divisors and out-of-range exponents
do not panic. The exponent test is **-scale in -6143..=6144**, as in Graph Node,
not significant-digit count minus scale. Extreme i64 scale inputs that make the
old dependency panic are refused before invoking it. Database parsing is
restricted to the host exponent domain. Error categories are stable; this crate
does not claim byte-identical AssemblyScript abort messages or gas accounting.

Integer operations use the pinned num-bigint arithmetic, including truncating
division and the sign of the remainder. The Graph Node bound includes a sign
bit: magnitude bit length + 1 <= 435412. Arithmetic methods represent the result
after its next checked crossing. Power and shifts take Graph Node's u8 count.
`to_i32_checked` enforces mathematical i32 bounds for transport validation.
`to_i32_mapping` reproduces the deployed graph-ts byte-array conversion: it
checks only sign-extension bytes beyond the first four and returns the low word.
Consequently +2147483648 becomes -2147483648, -2147483649 becomes 2147483647,
and -4294967296 becomes 0. The mapping conversion refuses values outside
-4294967296..=4294967295. Protobuf integers use minimal signed
big-endian bytes and empty bytes for zero.

The separate `mapping` module implements token conversion, safe division,
Q192-based price calculation with the deployed operation association, and
iterative tick prices. `TickPowTable` stores every 1024th value of the rounded
`1.0001` multiplication chain. Exponentiation by squaring changes rounding and
is not used. Token decimals are restricted to the deployed post-validation
0..=255 domain; ticks are restricted to -887272..=887272.

## Independent differential evidence

The committed fixture is generated by
[`mapping-host/tests/mapping_host/numerics_corpus.rs`](../../mapping-host/tests/mapping_host/numerics_corpus.rs).
That generator imports **Graph Node's real scalar types** and production
`FromAscObj<AscBigDecimal>` implementation. It never imports this crate. A small
byte heap provides AssemblyScript memory; API 0.0.7 headers, pointers, typed
arrays and decimal decoding remain Graph Node code. The raw threshold and both
neighbors are exercised through that decoder. This is an actual ABI conversion
test, not execution of an Aerodrome handler or a PostgreSQL `store.set` test.

For integer `toI32`, the oracle executes the **original deployed Pool.wasm
function body**, pinned by SHA-256. It adds one test export without changing
code, data, or globals. The original allocator and typed-array operations run
under Wasmtime. Only abort-message formatting is mocked; the original assertion
must reach `env.abort` for an overflow result. No handler or mapping initialization
is run. The portable crate has neither Wasmtime nor a WASM parser dependency.

The only shared code is the input-vector/PRNG generator. Evidence includes:

- Individual boundary vectors and 2048 seeded operation vectors, with exact
  coefficient, scale, canonical bytes, fixed-point flag and display hash.
- A SHA-256 commitment to every input and result in a 200,000-operation sweep.
  The portable crate replays all 200,000 and checks the digest, avoiding a large
  checked-in result dump. Seed and count are part of the fixture.
- Every 1024th iterative tick power through 887272, the first 64, and both last
  values, with reciprocals for negative ticks.
- All token decimal counts, Q192, the production negative TVL calculation,
  association differences, ±1/3, 2^116 boundaries, the raw Swap threshold,
  exponent boundaries, integer signs, zero division and overflow refusals.
- Decimal strings with 132,000 coefficient digits and a compensating exponent:
  string parsing normalizes before an integer ever crosses the WASM boundary,
  so a raw-coefficient BigInt bit limit would incorrectly refuse these values.

Regenerate deliberately, from the repository root:

```sh
UPDATE_NUMERICS_CORPUS=1 cargo +1.98.0 test --manifest-path mapping-host/Cargo.toml --locked --test mapping_host numerics_corpus
```

Without the environment variable the same command independently recomputes
everything and checks the committed fixture byte for byte. Normal verification:

```sh
cargo test -p graph-numerics --locked
cargo clippy -p graph-numerics --locked --all-targets -- -D warnings
```

Workspace CI runs the portable tests. The mapping-host workflow watches this
crate and checks regeneration against real Graph Node. No endpoint, token,
database or other live source is used.
