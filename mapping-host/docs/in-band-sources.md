# In-band dynamic sources for the mapping-host oracle

`graph-mapping-host run --data-sources-in-band --bcf1-out <path>` emits accepted,
deduplicated onchain dynamic source creations with their creating handler group.
It requires a separately generated descriptor v2 and refuses legacy sidecar and
sealed source-chunk options in the same run. Generate the descriptor with
`graph-mapping-host build-descriptors --data-sources-in-band --segments <directory>
--repo-root <repository>`.

The new protobuf message is `pinax.graph.backfill.v2.BlockChanges`, in
`common/proto/block_changes_in_band.proto`. Fields 1–8 have the exact v1 wire
layout and reuse its nested messages; field 9 carries `CreatedDataSource`.
The published v1 schema, generated binding, descriptors and frames retain their
bytes and identity. This refines S-C2's original proposal to extend the v1 schema:
its existing artifact pins explicitly name current files, so changing those
files while claiming historical hashes would violate source closure. Empty
creation frames round-trip through both codecs. A v1 canonical decoder refuses
field 9. The descriptor's message type and in-band capability distinguish the
extended envelope even though the established base contract string stays v1.

Creations require dense per-block ordinals, declared template/index pairs,
20-byte addresses, NULL context and ascending handler groups. A failed handler
group emits no accepted creation. A fatal block discards its creations and newly
instantiated hosts. A duplicate source request emits nothing. The validator
refuses a source from a failed group or any source in a fatally discarded block.
In-band frames require real observed block hashes; live sources additionally
check complete contiguous ranges, parent hashes and checkpoint boundaries.

`producer_contract.kind = mapping_host_oracle` binds the compiled source closure
and deployed bundle lock. It deliberately does not claim a Substreams package
or native reducer. `mapping-host/build.rs` hashes the root Cargo manifest, common
manifest/proto/source, mapping-host manifest/lock/build script/source and vendored
runtime. Files are sorted by repository-relative UTF-8 path. The hash input is
`pinax.mapping-host.source-closure/v1\0`, followed for every file by its path length
(u64 big endian), path bytes, byte length (u64 big endian), and raw SHA-256.
Symlinks are refused. Cargo tracks source directories and files for rebuilds.
The generated inventory lists SHA-256, length and relative path for each input.
Generated descriptors and tests are outside this closure, preventing a circular
identity. The bundle lock separately binds deployed WASMs, manifest, schema and
ABIs. This is a source identity; toolchain and candidate binary/image digests
remain separate evidence. Generation first verifies the full compiled file inventory against `--repo-root`,
refusing a stale or modified tree before writing either descriptor file.
The loader refuses a descriptor generated by another
compiled closure or for another bundle.

The `verify_in_band_oracle` example accepts seven paths: v1 descriptor, in-band
descriptor, retained v1 BCF1, fresh in-band BCF1, retained report, fresh report and
fresh checkpoint. An optional eighth path names the retained checkpoint; its
materialized entity/PoI rows, absent cache and dynamic inventory must match.
Cache residency is reported separately because equal-priority LFU eviction can
differ across processes; row identities, VIDs, values and Null/absent distinctions
remain exact. This does not prove arbitrary future checkpoint equivalence.
An optional ninth path names the initial in-band checkpoint for a continuation;
its boundary, descriptor, inherited sources and predecessor link are verified.
It streams and canonical-decodes both frame files, requires
complete observed coverage, checks payload/clock/report identities, and removes
only field 9 and replaces the compatibility ID to compare exact v1 bytes. Reports
must match in every field except envelope length/hash, including each entity
modification and PoI. The emitted creations must equal the checkpoint's runtime
inventory in order; the source-order commitment uses the existing source-v2
algorithm. Without the ninth path, the example requires an empty source
inventory at the range's start, as in Aerodrome R0 and R1. With it, inherited
sources are retained in order. Successful comparison proves equivalence to the
retained oracle evidence, not deployed indexer parity.
