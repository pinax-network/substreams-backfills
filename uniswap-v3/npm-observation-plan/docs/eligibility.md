# Eligibility boundary

## True in this tranche

- The host can enumerate the complete conservative NPM Position request set
  from the full source envelope.
- Once all Position rows are resolved, it can derive the complete conservative
  Pool and Token request sets from immutable block-start planning state and the
  exact segment profile.
- The planner covers all eight mainnet/Base history segments and every event
  after a would-be first fatal reducer result.
- Exact resolved-frame key equality, canonical source/state commitments,
  payload-free unstable-resolution refusal for the call scope and every
  observation, and exact cached-key consumption maxima are enforced before and
  after reducer invocation.

## False in this tranche

- No integrated provider executor evaluates these requests.
- Conservative request closure is not an exact Graph call trace: historical
  guards, missing identity, excluded pools, normal returns, fatal projection,
  and later Graph stages may leave planned rows unused.
- Factory/Pool handlers, dynamic data-source breadth-first stage order, Pool
  Transaction writers, persisted data sources, deterministic errors,
  EntityChanges/BlockChanges, VID allocation, and PoI are not combined here.
- No frame or reducer disposition authorizes Graph block success or a
  checkpoint.
- Boundary continuity, physical parity, PoI parity, backfill readiness, and
  production readiness remain false.

The next broader claim requires a deterministic host executor plus the missing
Factory/Pool and dynamic-stage/BlockChanges schedule. Provider or database
integration is a separate authority decision.
